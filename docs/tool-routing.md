# Tool routing (`tool_router.py`)

Tool definitions are most of the prompt (~2,700 tokens for all tools, against 90 for "hi" without them). So `select_tools(question, previous)` owns the whole choice: it takes the tools the preset allows (`prompts.allowed_tool_names`) and narrows them to the groups `_route()` picks, returning a `Selection(tools, groups)`. It embeds the question with `config.embed_model` and compares it with each group's examples (`GROUPS.examples`) and with `NO_TOOL_EXAMPLES`. Groups at or above `CONFIDENT` and within `MARGIN` of the best are sent. Otherwise small talk gets no tools, a vague question borrows the previous question's scores (`PREVIOUS_WEIGHT`), and so does a short follow-up (`FOLLOW_UP_WORDS`, `FOLLOW_UP_STARTS`: "and tomorrow?"; `FOLLOW_UP_ANSWERS` or any digit: "yes", "18 to 20", which answer something the model asked and otherwise score as small talk) even when it's confident on its own, since "tomorrow" alone matches calendar, and an unsure question gets the top `UNSURE_GROUPS` groups, because unknown names (a player, a show) score low. Tool routing is tested in `tests/test_tool_router.py`: rule tests use fake vectors in place of `mlx_client.embed`, and `LIVE_CASES` in `tests/test_live_routing.py` runs real questions through the embedding model (only with `LIVE=1`). Rerun it if you change the embedding model, the examples or the thresholds, and add examples rather than lowering thresholds. The groups live in `tools/tool_groups.py`: `ToolGroups` answers which groups some tools are in (`groups_of`) and which tools go with chosen groups (`is_sent_with`, `sent_with`), and is the only place that knows tools in no group are always sent (`search_library`, because examples can't cover what the user's files contain). Validation asks it the same questions, and `tests/test_tool_groups.py` tests the rule on a small `ToolGroups` of its own. Routing is skipped when the preset's tools sit in a single group, and any router error falls back to every allowed tool. Example embeddings are computed once per host+model. `Conversation.stream_reply` copies `Selection.groups` into `TurnInfo.tool_groups`, which shows on the usage line ("tools: cs").
