# Loaded file (`loaded_file.py`)

`Chat.load_file` awaits `loaded_file.load`, shows progress in the spinner and puts the result in `Conversation.file` (`/unload` and `/clear` drop it). A file up to `WHOLE_FILE_SHARE` of `context_length` is sent whole, at the end of the system message, where it's the same every turn so the server reuses its prompt cache. A longer one is chunked (paragraphs packed to `CHUNK_CHARS` with `OVERLAP_CHARS` carried over, each labelled "lines 120-148" or "page 3"), embedded with `config.rag_embed_model` on its own server (`docs/model-server.md`), and cached in `~/.cache/deckartes/embeddings` by path, mtime, size, model and chunk settings. Each turn `LoadedFile.context_for` picks the `TOP_K` chunks most like the question (or, at `PREVIOUS_WEIGHT`, the previous one, for follow-ups) and `Conversation` sends them as a system message just before the question, never stored in the history. `TurnInfo.file_context` shows on the usage line. EmbeddingGemma's task prefixes (`DOCUMENT_PREFIX`, `QUERY_PREFIX`) gave clearer matches than plain text. The excerpt prompt repeats its rule after the excerpts, because granite answered from its own knowledge when the rule came only before them. Top scores for questions the file can't answer overlap with real matches (0.56-0.67 vs 0.63-0.79 on a test file), so there's no relevance cutoff: every question gets excerpts. Cancelling `load` (ctrl+c) sets a `threading.Event` the loader checks between batches. `tests/test_loaded_file.py` uses real temporary files with only the embedding client and cache folder faked.
