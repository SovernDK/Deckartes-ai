# Loaded file (`rag.py`)

`Chat.load_file` runs `rag.load` in a thread, shows progress in the spinner and puts the result in `Conversation.document` (`/unload` and `/clear` drop it). A file up to `WHOLE_FILE_SHARE` of `context_length` is sent whole, at the end of the system message, where it's the same every turn so Ollama reuses its cache. A longer one is chunked (paragraphs packed to `CHUNK_CHARS` with `OVERLAP_CHARS` carried over, each labelled "lines 120-148" or "page 3"), embedded with `config.rag_embed_model`, and cached in `~/.cache/deckartes/embeddings` by path, mtime, size, model and chunk settings. Each turn `Conversation.file_excerpts` picks the `TOP_K` chunks most like the question (or, at `PREVIOUS_WEIGHT`, the previous one, for follow-ups) and `messages_for` sends them as a system message just before the question, never stored in the history. `TurnInfo.file_context` shows on the usage line. EmbeddingGemma's task prefixes (`DOCUMENT_PREFIX`, `QUERY_PREFIX`) gave clearer matches than plain text. The excerpt prompt repeats its rule after the excerpts, because granite answered from its own knowledge when the rule came only before them. Top scores for questions the file can't answer overlap with real matches (0.56-0.67 vs 0.63-0.79 on a test file), so there's no relevance cutoff: every question gets excerpts. A ctrl+c during embedding sets a `threading.Event` the loader checks between batches.
