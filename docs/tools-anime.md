# Anime tools (`animeschedule_api.py`)

Results are slimmed to name/rating/episodes/date and rated shows at or below `config.anime_min_rating` (0–10 scale, converted from the API's 1–100) are dropped. Unrated shows (`ratingCount` 0) stay, with `rating: None`, and sort last. They also sort last on the API side, so every page of a list is fetched. Timetables have no ratings, so they're matched by `route` against all `ongoing` anime, because season lists only contain premieres from that season. Timetable `week` is the ISO week, and `subPremier` is `0001-01-01` when unset. `_top_season` takes relative seasons ("next", "previous") so the model doesn't do season arithmetic. Upcoming seasons have few ratings, so it fills the top N with unrated shows by `trackedCount` and says so in the list's first line. `_continuing_shows` estimates the final episode from the next timetable episode plus the announced count at one a week, and answers `"unknown"` with a reason when either is missing. Each public function at the bottom of the module takes a tool's arguments and returns tool text, joining a private fetch step (slim dicts holding real values, such as datetimes) to a private wording step. List headers state shared context once (season, rating cutoff, "episode counts and premiere dates are given only when announced"), and unknown values are left out rather than spelled "not announced" on every line. `_user_list_text` groups shows under "Airing today/tomorrow/later this week/next week" headings, because small models filtered a flat list for "this week" unreliably. `_continues_text` leads with "will NOT be airing next season", because "continues next season: no." was read as a yes. Airing lines put the name first, because "14:31 FX Fighter…" was read as a channel called FX. The season list is capped at `MAX_SEASON_LIST`. A show matches when its English, romaji or main title contains every word of the name. When none does, `names.closest_by_words` picks the one show whose title has a close word (`fuzz.ratio` ≥ `WORD_CUTOFF`) for every word, and the tool text starts with `No show is named "…"; the closest match is:`. Whole-title scorers can't tell a short misspelt name from an unrelated one, so matching is word by word. Responses are cached for an hour (the limit is 120 requests per minute). Some anime have no `names` key. `_list_shows` reads `config.animeschedule_user`'s public list with the app token (the `/animelists/oauth` routes need OAuth2) and is read-only on purpose. It's cached for only 60s, and English names come from the ongoing-anime cache so they match the airing tool. Each entry also gets its next subtitled episode from this and next week's timetables, so questions like "which of my shows air this week" need one tool call. Small models don't reliably chain the day-by-day airing tool themselves.

`airing_digest` isn't a tool: it builds the morning Telegram message (`anime_digest.py`, see [telegram.md](telegram.md)). `_list_airing` joins the list to the day's timetable rather than using `_next_episodes`, which drops episodes that have already aired, and it ignores `config.anime_min_rating`, because the user chose those shows.
