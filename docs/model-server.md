# Model server (`mlx_server.py`, `mlx_client.py`)

Local models run in Rapid-MLX (`uv tool install 'rapid-mlx[embeddings]'`), in its own environment. `mlx_server` starts it as child processes and `mlx_client` is the only module that talks to it. `ToolCall`, `Delta` and `TokenCount` are what the rest of the app sees. `tool_schema.py` builds the tool definitions.

**Three servers.** A Rapid-MLX server holds one embedding model and rejects any other name. The chat server (`config.host`, started on mount) holds the chat model and `config.embed_model`. The embeddings-only server (`config.file_embed_host`) holds `config.rag_embed_model` and starts the first time the library is used in a session, by a load or a search. The decision server (`config.decision_host`, see below) holds `config.decision_model` for spending labels. Each call runs `ensure_chat`, `ensure_files` or `ensure_decisions`, so a crashed server returns on the next turn.

**Process rules.** A server already answering on a port is reused and never stopped. Logs are `~/.cache/deckartes/rapid-mlx-*.log`. Servers stop on exit through `atexit`; `/kill` stops them too, since there's no need for an unload call. The model is a launch argument, so `DecartesApp.set_model` restarts the chat server.

**Readiness.** Poll `/health/ready`, which is 503 until the model has loaded. `/v1/models` answers as soon as the port binds. The decision server has no `/health/ready`; it loads its model before it opens the port, so it's polled on `/health`.

**Model flags.** LFM3's 4-bit build isn't in Rapid-MLX's catalog, so `PARSER_FLAGS` names its parsers: `nemotron` handles the `<tool_call><function=` format. A new model family that doesn't auto-detect gets an entry there. Thinking is set per request (`enable_thinking`): on for chat turns (`config.enable_thinking`), always off for `complete()`, the compaction summary. The `qwen3` reasoning parser streams it as `reasoning_content`, apart from `content`, and `stream_chat` passes it on as `Delta.reasoning`. It counts toward `max_tokens` (8,192). It is never sent back: LFM3's template drops earlier turns' thinking anyway, and Rapid-MLX's message format has no field for it. The `--no-thinking` flag is a different thing: it leaves thinking tokens in the reply.

**EmbeddingGemma 2** must be a catalog build (`-4bit` or `-bf16`). Rapid-MLX loads those natively, and the `-8bit` build fails with "Model type embedding_gemma2 not supported".

**Prompt cache.** The server reuses the longest identical start of the prompt: about 0.15s to first token against 3s cold for 1,300 tokens on an M1. Keep the start of the prompt stable. The date is at the top, the time goes just before each question and is saved in the history with its turn. A different set of routed tool groups is a cold start, because tools are part of the first system block.

**Usage.** `prompt_tokens` includes cached tokens. Speed comes from `metrics.mean_itl_ms` on the finish chunk.

**Decision model.** Spending labels (`spending.py`) come from a decision model, not the chat model: it reads a state and one question and returns a probability for every option, without writing text, so the answer is always one of the categories. It's Decider-2b (a fine-tuned Qwen3.5-2B) served by `rapid-mlx system-one <folder> --backend decider` on its own port, through `/v1/systemone` (`mlx_client.decide`). `spending._labels` starts it when there are payees to label and stops it after (`stop_decisions`), since it takes about 1.7 GB loaded and 2.5 GB while scoring; a start with the model on disk takes about 8 s.

- **The model is made locally.** The release is bf16 only (3.8 GB weights, 4.7 GB running), so `src/model/quantize_decider.py` quantizes it to 4 bits (group size 64, embedding table included) into `config.decision_model` (`~/.local/share/deckartes/models/decider-2b-4bit`, 1.06 GB). It runs with Rapid-MLX's own Python, which has MLX: `~/.local/share/uv/tools/rapid-mlx/bin/python src/model/quantize_decider.py ~/.local/share/deckartes/models/decider-2b-4bit`. It downloads the pinned release into the Hugging Face cache; delete `models--nativ-community--decider-2b` there afterwards. A missing folder fails with that command in the message.
- **Calibration moved with quantizing.** Probabilities shift by about 0.08 on average against bf16, so the labeling limit is `config.spending_label_min_probability` = 0.5, fitted on the 4-bit model: on 22 known payees it labeled 11 right and none wrong, against 4 right and 12 wrong for LFM3. Re-check the limit after changing the model or the prompt.
- **Why not another one.** basal-1.5-mini (Polish) labeled as well, but takes at most 10 options and needs the option letters' logits after a prefilled answer, which Rapid-MLX's OpenAI endpoints don't give (`/v1/completions` returns only 5 log-probabilities, keyed by text). Laya (an encoder of about 300M) didn't know brands and labeled most payments as Cash.
- **Polish.** The question, the options' descriptions and the state's words are Polish (`prompts.json` `decisions`), since the payees are; English wording labeled worse on the 4-bit model.

**Tests.** `tests/test_mlx_client.py` uses `httpx.MockTransport` with SSE in the real server's shape, and `tests/test_mlx_server.py` runs a fake server program as the child. `spending` tests fake `mlx_client.decide` with `FakeDecisions` (`tests/test_spending.py`). The live tests (`tests/test_live_*.py`) use the real server and run only with `LIVE=1` and the chat server up. Run them after changing the model, the flags or the message format.
