# Calendar tools (`calendar_api.py`)

Apple Calendar through EventKit (pyobjc), so every calendar synced to the Mac is visible. EventKit is blocking: tools call it with `asyncio.to_thread`. The shared `EKEventStore` is made on first use, which shows macOS's permission prompt. The permission belongs to the parent app (Terminal, VS Code). A process that can't hold it (e.g. Claude Code's own shell) gets an instant refusal with the status still undetermined, so calendar access can't be tested from there (`docs/calendar-tests.md` has the fakes to use). `_events_between` calls `store.reset()` first: the store only learns about changes made in Calendar.app through notifications on a macOS run loop, which the app does not run, so a cached store misses new events. `parse_day` takes "today", weekdays ("next friday" is after today) and ISO dates, so the model doesn't do date arithmetic. `get_calendar_period` covers this/next week, this/next month, a month name or YYYY-MM, and multi-day lists say "days not listed have no events". `add_calendar_event` refuses past times (usually a wrong year from the model), skips an event with the same title and start that's already there (so a repeated "add NAVI's match" is harmless), and asks the user with `tools.confirm` before `save_event`. New events go to `config.calendar_name`, or Calendar's default calendar. Cross-tool requests ("put the next Frieren episode in my calendar") route to two groups because the same example question is in both `calendar` and `anime` (or `cs`).
