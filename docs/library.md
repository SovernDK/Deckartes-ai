# Library (`library.py`)

The library is the files the user saved, kept in one SQLite file at `config.library_path` (`~/.local/share/deckartes/library.db`, not `~/.cache`, because embeddings take long to rebuild and the original files may be gone). The model reaches it through the `search_library` tool. Nothing from it is added to a turn otherwise, and `/clear` doesn't touch it.

**Adding.** `Chat.load_file` awaits `library.add` with a file or folder from the explorer (key `e`: enter on a file, `l` on a file or folder), and the spinner shows each progress line. A file is chunked (paragraphs packed to `CHUNK_CHARS` with `OVERLAP_CHARS` carried over, each labelled "lines 120-148" or "page 3") and embedded with `config.rag_embed_model` on its own server (`docs/model-server.md`).

**Overwriting.** Files are identified by resolved full path, and adding one replaces only that file's row and its chunks. All of a file's chunks are embedded before one transaction deletes the old row and inserts the new one, so a failed or cancelled load keeps the old data. A file is skipped ("unchanged") when path, mtime, size, model and `SETTINGS` all match what's stored, because the stored data is already what an overwrite would produce, and re-adding a folder would otherwise re-embed all of it. Files deleted from disk stay until `/forget`.

**Folders.** `_files_in` walks recursively and keeps `FOLDER_SUFFIXES`, leaving out what Finder hides (`disk_scan.is_user_facing`), `SKIP_DIRS` and symlinks. A file picked by itself can have any suffix. In a folder, a file that can't be read (`_Unreadable`) goes in `AddResult.failed` and the load carries on, while any embedding or server failure stops the load, since every remaining file would fail the same way. Files finished before a stop stay saved. Cancelling (ctrl+c) sets a `threading.Event` checked between files and batches, and again just before the write.

**Searching.** `_searchable` keeps every vector of the current model in a normalised numpy matrix, rebuilt when `PRAGMA user_version` changes (`_mark_changed`, in every write transaction, so another running app's writes count too). A search takes the `TOP_K` highest dot products, best first, ties in stored order. 100,000 vectors of 768 dimensions: 0.57 s for the first search of a session, which builds the matrix, and 0.02 s after that, so brute force is enough. Embedding is the real limit on size. The sqlite-vec extension isn't an option because this venv's Python can't load SQLite extensions. Vectors from different models aren't comparable, so files saved with another `rag_embed_model` are left out until loaded again, and `/library` marks them.

**Tool text.** Passages are labelled `[file name, page 3]`. The rule to answer only from them is repeated after the passages, because granite answered from its own knowledge when the rule came only before them. Top scores for questions the files can't answer overlap with real matches (0.56-0.67 vs 0.63-0.79 on a test file), so there's no relevance cutoff. `search_library` is `@tool(None)`, sent with every question, because the router matches questions to example questions and can't know what the user's files contain.

**Embedding text.** EmbeddingGemma's task prefixes (`DOCUMENT_PREFIX`, `QUERY_PREFIX`) gave clearer matches than plain text. The document title is the file name, so a question naming a document ("my lease") matches chunks that don't repeat its name.

**Commands.** `/library` shows `library.report` as a message outside the conversation. `/forget <path or file name>` uses `library.matching` (starting with `/` or `~`: a file or everything under a folder; otherwise a file name in any folder, ignoring case) and asks through `Chat.confirm` before `library.forget`. The model has no tool that changes the library.

**Tests.** `tests/test_library.py` uses real temporary files and real SQLite with only `mlx_client.embed_file_text` faked, and `importlib.reload(library)` stands in for a new session. `tests/test_library_ui.py` drives the explorer and the commands with the pilot. Don't `await app.workers.wait_for_complete()` while the explorer is open, because `DirectoryTree`'s loader worker runs as long as the tree does.
