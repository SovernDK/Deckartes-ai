# Adding or changing a tool

## Adding a tool

Write an async function in `tools.py` with type hints and a Google-style docstring (`Args:` section), decorated with `@tool("<group>")`. Its body is one call to the backend, whose public function takes the tool's arguments and returns the tool text; fetching, normalising and wording stay private to the backend. The decorator adds it to `TOOLS`, `TOOLS_BY_NAME` and the group's `tools` list, and rejects a group that isn't in `TOOL_GROUPS` (defined at the top of the file, with the routing examples). `TOOLS` keeps definition order, which is the order the model sees the tools in. Ollama generates the schema the model sees from the name, signature and docstring, and marks every parameter as required even with defaults, so keep parameters few. Backends run blocking work with `asyncio.to_thread` themselves, and cap the size of returned text (see `web_search.MAX_PAGE_CHARS`) so results fit the context window. Docstrings say "home server (thinkpad)" vs "this computer" so the model can tell the Glances tools and the disk tools apart. Give each common question its own tool that answers it directly (e.g. `get_next_episode(name)`, not "check `get_anime_airing_on` day by day"). When a small model can't find the answer in a tool result, it makes one up, e.g. taking another row's time. For the same reason, return an explicit note when nothing is found rather than an empty list. Prefer returning short plain text with readable units (GB, %, °C) over raw API JSON, and include the reference values a model would otherwise guess, like limits and totals. `run_tool` passes `str` results through as-is and JSON-encodes anything else. Pick a fitting group or add a new one with its own example questions; `@tool(None)` puts a tool in no group, so it's sent with every question.

## Tool tests (`tests/test_*_tools.py`)

The wording and order of tool text are load-bearing, so these tests call the tools themselves with fake backend data and assert the exact text, and a wording change fails a test on purpose. Use `HttpTest.serve` (`tests/http_fake.py`) for HTTP responses and `freeze` (`tests/frozen_clock.py`) for the time and time zone. For calendar tests see `docs/calendar-tests.md`. `rag` has no such tests yet. `tests/test_disk_tools.py` uses a real temporary folder.

## Confirmation (`tools.confirm`)

A tool that changes something outside the app passes `tools.confirm` to its backend, which awaits `confirm(question)`. `Chat` sets `tools.confirm_handler` on mount. It pushes a `ConfirmScreen` (y / n / escape) and awaits a future its dismiss callback resolves. Interrupting while asking closes the popup. Without a UI, `confirm_handler` is `None` and changes go through.
